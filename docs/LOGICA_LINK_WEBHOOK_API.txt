+A pagina Webhooks de Links
+--------------------------
+Arquivo:
+frontend/app/pages/link-webhooks.vue
+
+Essa pagina e a interface onde admin ou lead configura para onde os webhooks de
+link serao enviados.
+
+Ela nao cria solicitacao de link. Ela so configura o recebimento dos eventos
+finais:
+
+- link_request.approved
+- link_request.rejected
+
+Ou seja:
+
+1. A Affiliate API cria a solicitacao usando usuario fake.
+2. O admin/lead/pool aprova ou rejeita no fluxo normal.
+3. O backend dispara o LinkWebhookService.
+4. A configuracao feita na pagina /link-webhooks define para qual URL esse
+   evento vai.
+
+
+Quem pode acessar a pagina
+--------------------------
+No frontend, a pagina tem:
+
+const canAccessLinkWebhooks = computed(() =>
+  user.value?.role === 'admin' || !!user.value?.hasReferrals,
+)
+
+Entao a UI mostra conteudo somente para:
+
+- admin;
+- afiliado que tem rede, identificado por hasReferrals.
+
+Se nao tiver acesso, renderiza um card:
+"Acesso restrito. Disponivel para administradores e afiliados com rede (lead)."
+
+No backend, a protecao real fica em:
+backend-vexxa/src/modules/link-webhook/infrastructure/admin-or-head-affiliate.guard.ts
+
+Guard:
+AdminOrHeadAffiliateGuard
+
+Ele permite:
+
+1. ADMIN ou SUPERADMIN:
+   acesso liberado.
+
+2. AFFILIATE:
+   so libera se tiver pelo menos um usuario com referredById = user.sub.
+
+Consulta:
+
+this.prisma.user.count({
+  where: { referredById: user.sub, deletedAt: null },
+})
+
+Se o afiliado nao tiver rede, retorna Forbidden:
+"Somente administradores ou afiliados com rede"
+
+Importante:
+O frontend esconder a pagina e so UX. A protecao de verdade e esse guard no
+backend.
+

+Como a pagina decide escopo global ou rede
+------------------------------------------
+Na pagina:
+
+const isNetworkScope = computed(() =>
+  settings.value?.scope === 'network' ||
+  (user.value?.role !== 'admin' && !!user.value?.hasReferrals),
+)
+
+Na pratica:
+
+- admin configura escopo global;
+- lead/afiliado com rede configura escopo da propria rede.
+
+Isso vem do backend em LinkWebhookSettingsService:
+
+ownerIdForActor(actor)
+
+Regra:
+
+- se role ADMIN ou SUPERADMIN -> ownerUserId = null;
+- caso contrario -> ownerUserId = actor.sub.
+
+Quando ownerUserId e null:
+scope = "global"
+
+Quando ownerUserId tem id de usuario:
+scope = "network"

+Entrega HTTP do webhook
+-----------------------
+Arquivo:
+backend-vexxa/src/modules/link-webhook/application/link-webhook.service.ts
+
+Metodo:
+postPayload(url, secret, payload)
+
+Headers enviados:
+
+- Content-Type: application/json
+- User-Agent: Vallex-LinkWebhook/1.0
+- X-Vallex-Event: payload.event
+- X-Vallex-Delivery-Id: payload.linkRequest.id
+
+Se houver secret configurado:
+
+- X-Vallex-Signature: sha256=<hmac>
+
+Assinatura:
+
+createHmac('sha256', secret).update(body).digest('hex')
+
+Timeout:
+
+LINK_WEBHOOK_HTTP_TIMEOUT_MS = 15000
+
+Se a resposta HTTP nao for 2xx, o backend trata como erro e salva FAILED.
+
+Se for 2xx:
+
+- status = SUCCESS
+- httpStatus = status retornado
+- responseBody = primeiros 4000 chars
+- attempts = 1
+- deliveredAt = now
+
+Se falhar:
+
+- status = FAILED
+- errorMessage = primeiros 2000 chars
+- attempts = 1
+
+
+Idempotencia da entrega
+-----------------------
+Arquivo:
+backend-vexxa/src/modules/link-webhook/application/link-webhook.service.ts
+
+Antes de postar, cria LinkWebhookDelivery com idempotencyKey:
+
+const ownerKey = settings.ownerUserId ?? 'global'
+const idempotencyKey =
+  `${ownerKey}:${linkRequestId}:${event}:${payload.linkRequest.fulfilledAt ?? payload.timestamp}`
+
+Esse campo e unique no banco.
+
+Se tentar criar uma entrega duplicada e o Prisma retornar P2002, o service
+simplesmente retorna e nao envia de novo.
+
+Objetivo:
+Evitar duplicidade de webhook para o mesmo owner/evento/request/momento.

+Como a pagina se conecta com a logica do usuario fake
+-----------------------------------------------------
+A pagina nao sabe que o usuario foi criado pela API. Ela so configura para onde
+o resultado final vai.
+
+A ponte entre as duas partes e esta:
+
+1. Affiliate API cria ou reutiliza usuario fake:
+
+   fake.referredById = ownerUserId do token
+
+2. LinkRequest e criada para o fake:
+
+   linkRequest.userId = fake.id
+
+3. Quando aprova/rejeita, LinkWebhookService resolve targets:
+
+   resolveTargets(linkRequest.userId, event)
+
+4. Para cada configuracao de lead, ele verifica:
+
+   isRequestInOwnerNetwork(settings.ownerUserId, linkRequest.userId)
+
+5. Como fake.referredById aponta para o owner do token, essa verificacao retorna
+   true.
+
+6. O webhook configurado na pagina /link-webhooks do owner recebe o payload.
+
+Resumo:
+
+Affiliate API = cria pedido em nome do fake.
+Pagina Webhooks de Links = configura para onde o resultado do pedido vai.
+referredById = cola as duas coisas.
